How the 3-Tier Engine Eliminates Context Bloat and Focus Theft

        

          In an LLM tool loop of N turns where each step appends a snapshot of size S, total billed input tokens grow quadratically as ½·N²·S. faster-mac-use attacks both factors simultaneously: collapsing N via a stateful cua_repl sandbox + Virtual WebMCP macros, and shrinking S via persistent UIDs, pre-registered table folding, push-based AXObserver dirty tracking, and stale-observation masking.
        


        

          

            
Tier 1: Browser Engine, Extension WS Bridge & Canvas OCR

            
    
              
  • Outbound MV3 Extension WebSocket Bridge + Headless Worker: extension/background.js connects outward to ws://127.0.0.1:19222/ext (single-daemon owner via /tmp/fmu-runtime.sock, inspectable via cua.getBridgeStatus()) to drive live logged-in Chrome "🤖 Agent" tab groups (active: false, with window / windowId / reuseExisting targeting) with zero Chrome 144 DevToolsActivePort modal popups, paired with a background Playwright worker with CDP Focus Emulation.
    • 
              
  • Pre-Registered Table Folding: Assigns persistent WeakMap @u1..@uN UIDs and folds dense <tbody> rows beyond the first 6 while indexing all rows in uidToRef, cutting initial snapshots from 1,520 to 810 tokens while keeping folded rows clickable by label or UID.
    • 
              
  • Native & Virtual WebMCP Macros (~/.fmu/macros/): Auto-detects navigator.modelContext tools and lets agents synthesize multi-step trajectories into reusable 1-turn Virtual WebMCP tools (tab.saveMacro → tab.callTool).
    • 
              
  • Rich-Text DOM Engine, 0-Token <canvas> OCR & File Uploads: Deterministically replaces or appends (append: true) multi-block contenteditable / Draft.js / ProseMirror editors in <50 ms without touching the OS clipboard, clips <canvas> into Apple Silicon VNRecognizeTextRequest (@ocr1..@ocrN), and injects files via DOM.setFileInputFiles without opening NSOpenPanel.
    • 
            

          


          

            
Tier 2: Native Swift AXObserver & Vision OCR

            
    
              
  • Persistent Unix Socket Daemon (/tmp/fmu-ax.sock): Universal2 Swift binary (fmu_ax.swift) maintains a 4,000-element AXUIElement LRU cache, PID/window cache, and per-agent diff baselines across turns.
    • 
              
  • Push-Based AXObserver Dirty-Subtree Tracking: Subscribes to kAXValueChangedNotification, kAXCreatedNotification, and kAXUIElementDestroyedNotification on a dedicated CFRunLoop thread so Turn 2+ unchanged or leaf-dirty diffs return in < 1 ms.
    • 
              
  • Non-Destructive Hygiene & Multi-Window Guards: Fetches attributes with AXUIElementCopyMultipleAttributeValues, never overwrites NSPasteboard.general on op: "set" (verifying AXTextArea read-back and detecting NSOpenPanel TCC-disabled Open buttons), and guards CGEvent.postToPid key routing on non-main windows.
    • 
              
  • 0-Token Apple Silicon Window OCR: Built-in CGWindowListCreateImage + VNRecognizeTextRequest fallback (await app.ocr()) reads GPU/canvas windows in <70 ms with zero LLM vision tokens.
    • 
            

          


          

            
Tier 3: Multi-Cursor REPL & Context Guard

            
    
              
  • 268-Token Single-Tool Schema & Strict Step Validation: Supports OpenAI Codex-style stateful cua_repl scripts (cua.createBrowserTab, cua.getApp, cua.getBridgeStatus, cua.saveMacro, cua.getCursors), 1-trip declarative steps batches (normalizing op/action, uid/target, and value/text with explicit missing-op errors), and concurrent {"parallel": [...]} swarms.
    • 
              
  • Per-Agent Virtual Cursors: Each agent ID (agent-1, agent-2, ...) gets an isolated AgentSession, independent DOM/AX diff baseline, and independent virtual cursor coordinates (tab.moveCursor / app.moveCursor).
    • 
              
  • Stale-Observation Masking: ContextWindowTracker replaces superseded full snapshots from earlier turns with 18-token tombstones, keeping 30-step peak context at 1,597 tokens.
    • 
              
  • 50Hz Intrusion Guard: Polls CoreGraphics (CGEventGetLocation + CGEventSourceSecondsSinceLastEventType) and lsappinfo front to prove 0.0 px physical cursor movement.
    • 
            

          

        

      


      

        
Broader Market Comparison & Material Boundaries

        

          Computer-use tools in 2026 fall into four architectural generations. Here is where faster-mac-use wins against the broader market and the exact platform boundaries to keep in mind (read the full market & GTM brief and launch kit).
        


        

          

            
Where faster-mac-use Wins Across the 4 Generations

            
    
              
  • vs. Gen 1 Pixel Screenshot Loops (Anthropic computer tool, Operator): Pixel loops capture full-screen images every step (83k–620k cumulative tokens) and hijack the physical Mac cursor unless isolated in a VM. fmu operates directly on your host Mac in the background at 0.0 px drift and 40×–135× lower token cost.
    • 
              
  • vs. Gen 2 Verbose Browser/OS MCPs (@playwright/mcp, chrome-devtools-mcp, open-computer-use): Standard MCPs charge a 1,508–12,592 token schema tax every turn and dump full ARIA trees on every click (143k–231k tokens on Workload A). fmu uses a 268-token schema and returns compact +/~/- UID diffs (2,024 tokens, or 1,290 with WebMCP / Virtual Macros).
    • 
              
  • vs. Gen 3 Single-Surface Ref CLIs (vercel-labs/agent-browser, @playwright/cli, Peekaboo, trycua/cua): Sequential ref numbering suffers index-shift diff avalanches when banners insert at the top of the DOM, and separate web vs. Mac tools cannot coordinate in one turn. fmu unifies Chrome and native macOS AX with persistent WeakMap / CFHash UIDs and push-based AXObserver tracking.
    • 
              
  • vs. Gen 4 Single-Session REPLs (OpenAI Codex cua_repl): Codex's cua_repl is the strongest closed-source design, but serializes multi-agent UI work into a single session. fmu adds true multi-cursor parallel swarms (cutting 3-agent 25-op tokens by 10.5× and engine time by 3.4×), auto-synthesized Virtual WebMCP macros, pre-registered table folding, and 0-vision-token Apple Silicon Window + <canvas> OCR.
    • 
            

          


          

            
Material Limitations & Field-Tested Guardrails

            
    
              
  • macOS-first native tier: The compiled Swift accessibility and Vision OCR daemon (src/native/fmu_ax.swift) requires macOS (Apple Silicon / macOS 14+ recommended) with Accessibility permission granted to your terminal or host IDE.
    • 
              
  • Single-daemon :19222 bridge & explicit MV3 bridge diagnostics: Driving color-coded "🤖 Agent" tab groups inside your primary logged-in Chrome window uses the MV3 extension's outbound WebSocket bridge (extension/ → ws://127.0.0.1:19222/ext, owned exclusively by /tmp/fmu-runtime.sock and inspectable via cua.getBridgeStatus()). When mode: "extension" (or "live" / requireExtension: true) is requested without the extension connected, fmu fails fast with a clear setup diagnostic; when default mode: "chrome" targets an external URL while disconnected, fmu tags the header bridge="headless-fallback" and emits an explicit ! warning:; in mode: "headless" or on local dev URLs, it runs out-of-the-box in an isolated background Chromium worker with CDP Focus Emulation.
    • 
              
  • Web rich-text editors (contenteditable / Draft.js / ProseMirror) & NSOpenPanel TCC: On sites like X and RedNote, macOS Accessibility exposes multi-block contenteditable editors as a single AXTextArea whose kAXValueAttribute does not fire DOM beforeinput state updates, and clicking web upload buttons via AX opens macOS NSOpenPanel where AppKit/TCC locks the Open button. Always drive web rich-text editors (supporting deterministic replace and append: true) and file uploads through the Browser DOM tier (surface: "web" / CDP DOM.setFileInputFiles); fmu-ax never overwrites NSPasteboard.general and surfaces explicit ! errors: diagnostics when AXTextArea read-back or NSOpenPanel TCC blocks synthetic AX actions.
    • 
              
  • Multi-window background key routing & minimized window OCR: While AXUIElement reads and AXPress actions work on any background or minimized window (and cua.createBrowserTab supports window / windowId / reuseExisting Chrome window routing), macOS routes CGEvent.postToPid keystrokes to an app's AXMainWindow and unloads pixel backing stores for Dock-minimized windows. fmu-ax guards non-main-window key routing, and app.ocr() requires the target window to be unminimized (it can remain completely occluded behind other windows).
    •
